# Roban2 蓝牙手柄：前伸／后缩和腕部夹持

## 按键

| 按键 | 功能 |
| --- | --- |
| 按住 Y | 双臂向前伸；松开停止并保持 |
| 按住 A | 双臂向站立时收回位置运动；松开停止并保持 |
| 按住 L3（左摇杆按下） | 两腕向内合拢；松开停止并保持 |
| 按住 R3（右摇杆按下） | 两腕向外张开，释放物体；松开停止并保持 |
| B | 软件急停：控制器原生 Quit；与 A/Y/L3/R3 同按也支持 |
| BACK + START | 原有系统退出组合键 |

## 腕部操作

新增动作只控制手臂关节，按拆除灵巧手后的腕部安装点计算间距，不发送手指指令。
先按 Y 把双臂前伸至少 60°，再松开 Y、单独按住 L3 合拢。
需要释放物体时按住 R3 张开。L3/R3 是垂直按下摇杆，摇杆偏离中心会中止动作。
四个动作键均需单独按住约 0.25 秒；松开停止并请求 KeepPose。

合拢／张开速度上限 0.08 rad/s；模型中的两腕安装点中心间距下限为 18 cm，
这不是接触面净距，也不表示能夹住任意尺寸物体。按键到限位会停止，需松开再按。
Y/A 保持两腕的左右坐标；两腕收进肩宽以内时，A 最多收到前伸 60°，
需先用 R3 张开后才能完全收回，避免腕部向躯干靠近。

这是位置控制，松开按键保持位置；没有恒夹紧力控制，也没有验证夹持承重。
实物宽度、质量、接触面和拆手后的机械尺寸仍需现场核对。先空载验证方向和停止，
夹持测试时让物体有支撑，确认稳定后再尝试承重。

A/Y 单独持续按下约 0.25 秒后开始，避免与原有组合键冲突。单关节速度不超过
0.18 rad/s（约 10.3°/s）。到达前伸或收回端点自动停止；不会伸到端点之外。
它控制双臂的八个关节，不发送腿、腰、头或手指指令。

仅在 AMP 控制器运行、机器人静止且姿态正常、手臂处于 Auto/KeepPose 模式、
反馈新鲜且当前关节位于既定行程附近时接管。松手、摇杆移动、其他按键、
输入或反馈超时、模式改变、其他程序发出手臂指令时停止。停止或失联后需
先松开按键，再重新按住，不会因恢复连接而自动续动。

前伸端点取自机器人现有 `前伸双手.tact` 第 100 帧的前八个关节。
收回端点取自 v17 `config_amp.yaml` 的 `start_stand_pos` 手臂部分。
不播放原动作中的手指、头部或自动收回段。B 的 Quit 是软件退出控制，
不等同于硬件断电急停。

## 部署位置

- 下位机 `/home/lab/roban2-gamepad/`：源代码、程序和测试。
- 下位机 `/etc/systemd/system/roban2-arm-jog.service`：开机启动服务。

- `/root/.config/lejuconfig` 是上述 lab 配置目录的软链接，控制器实际加载同一份配置。
- 上位机 `/home/leju_kuavo/roban2-gamepad/`：本说明和配置快照。

仓库原有模板和动作文件保持原样。A/Y 连续控制由独立服务读取同一手柄数据实现，
不依赖修改控制器二进制。原有组合键先按 LB/RB/LT/RT 等修饰键。

## 检查和停止扩展

```bash
systemctl status roban2-arm-jog.service --no-pager
journalctl -u roban2-arm-jog.service -n 40 --no-pager
sudo systemctl disable --now roban2-arm-jog.service
```

停止服务停用 A/Y/L3/R3 连续手臂控制；B 软件急停仍留在运行配置中。
修改前的配置备份以 `teleop_bindings.yaml.before-roban2-gamepad-` 开头，位于同目录。

## 验证范围

`test_jog_core.cpp` 检查边界、速度、组合键、松开、重连和输入失效。
`test_wrist_urdf.py` 对实际 URDF 的双腕安装点做 1000 组姿态的独立矩阵计算，
核对 C++ 核心计算。腕部间距限制不是完整的机械碰撞检测。
`test_integration.py` 在**仅回环网卡、DDS 外部域 217、专用 Tag、禁用共享内存**的
隔离环境运行实际程序与模拟反馈，验证持续运动、松手保持、断连／反馈失效、
其他控制程序接管、B 中止等逻辑，不连接真实电机。

真实机器只运行过 `--observe` 读取输入和反馈。本次未通过远程工具触发真实
手臂运动或急停；机械行程、实机停止效果仍需现场验证。

该机器启用共享内存时，原生状态查询出现崩溃，Python 查询也收不到回复。
经真实控制器只读验证，扩展服务使用自己的 `dds-network.xml` 关闭共享内存，
通过同一内部网卡的网络 DDS 正常通信。机器原有全局 DDS 配置未修改。
`status_monitor.py` 通过已有的 Python DDS 协议定义查询状态；它只调用两项
Get 服务，不发送运动、启动或模式指令。
`_rpc_lib.py` 是从下位机已有的 `/home/lab/box_test/_rpc_lib.py` 复制的独立依赖。
