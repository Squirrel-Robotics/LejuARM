- 已用独立 C++ SDK 子进程实际发送头部参考：目标 pitch 为下俯 **35°**，反馈约 **33.6°**，yaw 约 **0.59°**。这是约1.4°的稳态误差，尚未做精度标定。
- 持续发送时，头部下视画面能看到桌面与黄色海绵。**停发后，本次机器人自动回到约1.73°的原俯仰角。** 因此有限时长测试结束后拍照，可能已经不是低头画面。
- 未发送手臂、腰或腿部运动指令，未进行抓取。

35°原型实测证据保存在相邻的 `2026-10-20_头部旧SDK独立控制/evidence/`。2026-10-21已验证AMP下长时间保持和HEFT切换后保持，记录见相邻的 `2026-10-21_头部35度部署验证/`、`2026-10-21_HEFT与头部并行验证/`。本次范围修改不自动执行37°或45°实体运动。

## 2026-10-29 beta 主控头部死区：发现与补偿

10-28 部署 beta 分支主控（`run_rl_controller`，经 `launch_teleop_real.sh` 启动）后，本脚本连续 `HEAD_NO_RESPONSE`。逐层对照排查（新旧分支脚本与 SDK 二进制行为一致、消息抓包与官方工具一致、官方 `dds_head_pose_test.sh` 同样 FAIL）确认根因在**主控头部通道行为变化，与本脚本和旧 SDK 无关**：

- beta 主控只在**命令领先实测角约 6° 以上**时才开始驱动头部，随后保持 **6–7° 恒定滞后**跟随，稳态停在目标−6.5° 附近（实测：命令 30° 停在 23.8°；旧版主控滞后仅约 1.4°）。
- 旧判定"`elapsed>2s` 且命令离开初始 3° 即要求实测跟随"在慢速轨迹下必然误判：2s 时命令领先仅约 4°，仍在死区内，脚本过早退出。

本版修改（已部署至下位机并真机验证，实测 36.5° 目标到位 36.24°，误差 0.26°）：

1. 命令偏置：发布 `目标 + 6.5°`（钳到 45° 上限），新增参数 `--deadband-compensation-deg`（默认 6.5，0=禁用，范围 0..15）。yaw 不补偿（其死区未实测）。
2. `HEAD_NO_RESPONSE` 判定阈值：命令领先 3° → 10°（越过死区才判"该动没动"）。
3. 到位/保持判定对**原始目标**做容差判定（2026-10-30 起默认 ±1°，参数 `--target-tolerance-deg` 0.3..3°）；未达标时进入自适应修正：每 0.5s 命令偏置 ±1°（钳 45°），最多修正 12s。报告含 `deadband_compensation_deg` 与 `deadband_compensation_applied_deg`。
4. `HEAD_PUBLISH_LOOP_GAP` 阈值 150ms → 450ms（控制器新鲜度窗口 0.5s，偶发调度抖动不再中断保持；2026-10-29 晚 5 分钟保持被 150ms 抖动误杀后调整）。

注意事项：

- 目标接近 45° 时补偿会被钳制，实际将停在 45°−死区 附近且判定不到位——这是 beta 主控下的物理上限，不是脚本问题。
- 若下位机切回旧分支主控（无死区），需加 `--deadband-compensation-deg 0`，否则会过冲约 6.5°。
- 官方工具 `src/leju_launch/scripts/dds_head_pose_test.sh` 在 beta 主控下同样受死区影响（30° 用例 FAIL 6.18°），可作主控行为的快速复核。

`--execute` 会在适配器缺失或源码较新时自动编译。依赖下位机现有 `g++`、`installed` 旧 SDK 和 Python CycloneDDS；`LEJULAB_PROJECT_ROOT` 默认 `/home/lab/yss/Lejulab_ARM`。未修改系统 DDS 配置或机器人硬件配置。


头部发送目标为 **50Hz**，沿用本次已成功运动的原型设置；这是独立头部轨迹接口，与21关节 HEFT 的100Hz默认参考流分别配置。Python 调度不提供硬实时保证。

## 运动边界和记录

- pitch目标允许 **−20°～45°，含两个端点**，下俯为正；yaw反馈和SDK发布范围同步为−90°～90°，仍使用本次最新yaw并保持，不新增yaw运动输入。默认7秒平滑运动；跨度较大时自动延长以限制参考速度至8°/s。
- 初始状态需为稳定 `amp` 或 `heft_pico`。持续只读观测控制器，不调用切换模式服务。
- 23关节反馈同时检查源时间戳和接收时间，超过0.25秒不再发布。控制器状态过期、发布循环间隔超过0.15秒、SDK拒绝或无回复时停止。
- 检查yaw偏移、头部反馈范围、明显无响应；运动结束3秒后需在目标2°以内，并在保持阶段继续检查。失败不报告为成功。
- 同一台机器通过锁文件禁止本脚本的多个执行实例。该锁不拦截Pico、旧测试程序或其他头部发布程序；现场应确保头部只有一个指令来源。
- 头部SDK与Python DDS分进程运行，避开本机发现的混用问题。C++适配器支持 `INIT/PUB/CLOSE`，新增 `CHECK` 仅检查与实际发布共用的参数保护，不初始化SDK、不发布指令。适配器不调用旧SDK状态RPC或 `SetHeadMode`。只读控制器观测使用已验证的Python RPC实现。
- 只对当前进程关闭DDS共享内存，保留所选网卡、发现设置；子进程继承同一配置。系统 `/etc/cyclonedds/cyclonedds_shm.xml` 保持不变。

每次启动会写入独立的 `validation/时间_进程号_编号/`：

```text
session_status.json   到位判定、最后实测角、帧数、退出原因
samples.jsonl         约5Hz的参考与反馈记录
```

正常退出、Ctrl+C及可捕获异常会保存状态。断电或进程被强制杀死时，最后退出原因可能无法落盘。`body_commands_sent=0` 表示本程序的发送范围，不代表身体主控停止运行。
