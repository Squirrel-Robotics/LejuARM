# Roban2 数据采集处理 · 第一版

局域网入口：http://192.168.110.88:8877/ ，同一局域网的同事可以访问。本机也可继续使用 http://127.0.0.1:8877/ 。网页与接收处理服务均配置为用户登录后启动。

## 使用顺序

1. 确认本机开机、外置数据盘已挂载，启动下面两个服务。
2. 按原流程在下位机执行 `src/leju_launch/scripts/launch_teleop_real.sh`。启动硬件后、启动主控和Pico之前，会等待23维关节反馈检查（最多12秒）；失败时退出并清理本次启动的子进程。根用户通过lab用户的系统Python执行检查，保留启动器的DDS配置。
3. 网页顶部独立显示关节反馈检查与23个关节的位置、速度和力矩；它不依赖录制监听器已经启动。检查数据持续更新≥200ms、最后源数据年龄≤150ms、23维q/v/vd/tau完整且全部有限；不要求关节运动或角度非零。这是DDS反馈数据检查，不是每台电机故障码诊断。
4. 等全部采集条件就绪，先点击“新建任务”定义任务名称，再选择采集任务、L/R左右手（可选）、填写Prompt和采集人，点击“应用任务”。任务在每段开始时按recording_id固定，采集中与收尾时禁止更改。
5. LT+Y或网页“开始本条”开始；LT+X或网页“停止本条”结束。两者共用同一个下位机录制状态机，网页不发布机器人动作。停止录制不停止机器人运动。
6. 结束后自动传输校验和本机处理。绿色“可以开始下一段”依据下位机收尾与采集就绪；绿色“原始数据已校验，可关闭下位机”依据全部数据已持久保存、SHA256校验、下位机缓存清理回执与无活动/待传会话。本机裁剪不必完成才能开始下一段或关闭下位机。

```bash
systemctl --user start roban-vr-dashboard.service roban-vr-workstation.service
systemctl --user is-active roban-vr-dashboard.service roban-vr-workstation.service
journalctl --user -u roban-vr-dashboard.service -f
journalctl --user -u roban-vr-workstation.service -f
```

不使用sudo。浏览器关闭或刷新不影响后台录制与数据处理。

## RGB与数据质量

上位机RGB原始录制与实时预览目标均为60FPS，网页分别显示相机源FPS、预览接收FPS与浏览器绘制FPS。预览复用已有ROS压缩图像，不重新打开摄像头，不读取正在写入的MP4；所有浏览器共享本机一条上位机预览订阅，慢客户端只获取最新预览，不积压旧画面。过期图像与连接状态会明确显示。预览以接收端逐帧请求最新图像，SSH链路最多一帧在途；网络变慢时跳过中间预览帧，不排队补播。RGB与深度均显示保守时延上界，结合上位机源帧年龄与本机单调时钟请求耗时计算；累计年龄超过700ms的帧不显示为实时，深度读距同时清空。

正式视频和逐帧时间戳完整保留。本机按同一源时间区间首尾各裁5秒，再生成连续20ms网格，以该时刻及之前的最新真实动作/状态/RGB进行因果对齐；不插值、不使用未来帧、不静默删除内部不合格行。阈值保持：参考50ms、状态50ms、RGB40ms，时钟不确定度5ms。

停止后检查MCAP全量CRC、视频解码、视频帧与时间戳行数、时间戳和序号间断、录制队列丢帧、传输哈希及全量连续网格。原始动作消息数、裁剪MCAP参考数、50Hz网格样本数分别显示；重复使用真实参考有明确的源索引，不能把网格50Hz当作参考实际频率。

“通过但有提示”可能表示对齐全通过但相机存在较长时间间隔。相机源时间间隔与源序号缺失分开报告，不把时间间隔推测出的缺帧数量当作已确认序号丢失。

## 实时深度预览（2026-10-30）

上位机相机为Orbbec Gemini 335 RGB-D。采集工作台并排显示RGB与深度伪彩图，均使用已有相机ROS输出，目标60FPS。深度订阅`/roban2_stage0_camera/depth/image_raw`，当前为640×480、16UC1毫米数据，已配准到RGB视角。驱动已将传感器深度比例转换为毫米；网页原始整数除以1000显示米，不从伪彩色反推距离。

默认启用AUTO RANGE自动色阶，自动跟随当前有效深度范围，增强近处物体的深度层次。近端/远端显示当前自动范围；切换MANUAL可手动设置，来回切换保留本页上次有效手动范围（初始0.2/3米）。刷新页面仍默认自动。无效手动范围提示错误并保持上一份有效色表。范围外有效测量使用端点颜色。

自动色阶每200ms从完整16位深度图统计有效值的第2/98百分位，排除0值和少量极端值；采用650ms时间常数平滑，并保持至少0.1米显示跨度，减少抖动和静态平面噪声放大。自动模式采用逆深度色阶，避免远处背景压淡近处物体的层次；手动模式保留线性色阶。断流恢复或切换自动模式时重新估计，整帧无有效值时提示等待。自动色阶的颜色不代表跨时刻固定的米制间隔，测距以数字和当前近远范围为准。

默认显示中心像素深度，鼠标指向或点击深度图可查看对应像素的深度；移出恢复中心。显示的是沿相机光轴的深度，不是相机到该点的欧氏距离。黑色表示传感器未提供有效测量，显示“无有效深度”。色阶仅改变显示颜色，鼠标测距始终读取原始毫米值，不填补无效深度。

深度图通过上位机只读脚本`/home/leju_kuavo/vr_vision_recorder/vr_dashboard_depth.py`无损压缩传输，本机共享一条订阅，各网页只接收最新帧。网页保留16位数值用于读距，分别显示源、接收和绘制FPS；浏览器不支持解压接口时自动使用本机解压。700ms未绘制新帧即覆盖过期提示并清空距离，避免误看旧值。画面显示的时间差仅比较最近显示的RGB/深度源时间戳，不代表采集文件的50Hz对齐检查。

用户指定仅实时查看：不保存深度视频或逐帧深度，不改变RGB、MCAP、首尾裁5秒或50Hz训练对齐输出。深度预览不作为开始录制的额外前置条件。相机服务提供深度后，现有`roban-vr-dashboard.service`自动连接，无需新增启动命令。

## 50Hz动作与视频联动审核（2026-10-28）

“采集记录 → 查看 / 审核”默认打开联动界面。审核预览的第N帧严格来自第N个网格样本的`rgb_frame_index`，以50FPS封装；从真实源视频按索引抽取和重复帧，不插图、不插值。原始60FPS录制与训练输出不变。首次打开需几秒生成，之后复用`.pipeline/review_cache/recording_id/v2_<源文件签名>/aligned_preview.mp4`。这是可再生成的网页缓存，不是交付训练的数据。

播放、拖动播放器或样本滑杆时，当前样本、源帧、参考/反馈索引、关节值、曲线游标一起变化。支持0.25×/0.5×慢放、上一条/下一条（20ms）、指定编号后点“定位”、上一个/下一个异常。暂停时可展开全部21个关节。

界面显示参考、反馈、RGB距网格的年龄及各自阈值（50/50/40ms），超时标红；曲线用红线标记失败点。原始参考更新Hz与50Hz网格是不同指标；关节跟踪误差也不是时间差。数值与源时间戳以MCAP及逐帧时间戳为准，ns用字符串传输以保留整数精度。播放器按审核视频的帧PTS定位样本，避免按原始60FPS视频的CFR秒数推断MCAP源时间。

处理失败的完整片段也可以进入诊断视图：仅在内存中按相同裁剪、因果取样和阈值重建网格，显示真实有效的源角度及超时原因；不删除失败点，不补回参考，不改写`raw`、`processed`、`status.json`或训练结论。诊断索引指向原片/原MCAP；合格审核索引指向已保存的裁剪文件，并额外显示原片帧号。时钟检查失败会单独提示。缺少必要源文件或时间戳倒退时拒绝生成误导性的审核预览。

“独立回看原始 / 裁剪60FPS视频”用于完整上下文浏览，与上方联动审核区分开。关节名称映射与腰部显示方向沿用已验证的S17规则。

## 机器人3D联动审核（2026-10-28）

审核页将RGB视频与Roban S17的3D模型并排显示。模型使用本机`.pipeline/urdf/biped_s17.urdf`和`urdf/meshes/`下的28个配套STL；URDF与下位机版本SHA256一致。Three.js 0.186.1及插件本地保存于`dashboard/static/vendor`，页面无CDN或外网依赖。

默认绿模型显示21关节参考动作；可切换蓝色23关节实际反馈，或用绿参考＋半透明蓝实际叠加对比。实际反馈按现有S17硬件顺序转到模型关节名称，腰部取源索引12并乘−1，头部索引21/22对应`zhead_1_joint`/`zhead_2_joint`。21维参考不包含头部，因此参考模型头部固定为中立位。基座位置固定，不从关节角虚构机身平移/朝向；模型仅作关节姿态回放。

模型复用当前视频帧定位的同一50Hz样本，没有独立计时器，也不对角度插值。播放、拖动、20ms单步、编号定位、异常跳转和慢放一起更新3D、曲线与数值；不合格样本在3D状态条也明确提示。角度缺失时隐藏对应模型，避免误显示上一条姿态。关节值不按URDF限位夹紧，保留真实记录，人工可观察越界情况。

左键拖动旋转、滚轮缩放；“正面 / 侧面 / 复位视角”调整相机。关闭审核会取消加载、停止绘制并释放WebGL资源，不影响后台录制服务。模型接口只读，网格接口只提供当前URDF引用的文件名，拒绝路径穿越与符号链接。

## R/L归档与删除（2026-10-28）

在“采集记录”中勾选记录后，可批量“归到R·右手”“归到L·左手”或“删除所选”。R/L由操作人选择，不根据动作数值自动推断。新录制仍先放根目录，等待人工审核与归类；无效数据也由操作人确认后删除，不会根据技术质量自动删除。

归档按整个会话移动到`vr_Data/R/时间目录/`或`vr_Data/L/时间目录/`，原始MCAP、RGB、时间戳、裁剪结果和episode.json标注一起保留，可再次改归另一侧。筛选器支持R、L、未归档与回收站。目录冲突时停止，绝不覆盖另一段数据。

“删除所选”会先列出选中的会话，确认后把完整会话移到`vr_Data/.trash/时间目录/`。删除后从正常采集记录中隐藏；在筛选器选“回收站”可逐段或批量恢复，恢复到删除前的原位置（R、L或未归档）。这不是永久删除，不会立即释放磁盘空间。本版不提供清空回收站/永久删除接口。传输、缓存清理未确认或本机处理中暂不可归档、删除；未接收的下位机异常记录仍按原流程保留。

`recording_id`和`local_session`保持稳定，`.pipeline/transfers/`中新增`local_path`指向当前位置。接收、重试处理、标注、下载、视频及3D审核按当前位置读取；避免目录移动后接收服务重新生成旧位置。时间目录名称在根、R、L和回收站间保持全局唯一。

移动仅改会话位置，raw/processed内部文件字节和哈希不变；文件内的历史绝对路径作为采集/处理历史保留。会话级`location.json`、`receipt.json`和`status.json`记录当前位置，归档/回收日志在`.pipeline/archives/`。目录移动与索引更新有跨进程锁、预写日志和中断恢复，接收服务与网页会恢复未完成操作；回收站记录不会被后台自动处理或重新出现。


## 未传到本机的异常记录：永久清理缓存

在采集记录行末点击“删除异常缓存”。弹窗列出具体会话编号、录制编号和清理范围；确认后清理下位机MCAP/视觉缓存及上位机对应JPEG、视频和时间戳。此操作不可恢复。已传到本机的数据仍使用原有“删除所选 → 回收站”流程。

适用条件：下位机状态实时可用；该段未发布传输清单；本机没有该录制编号的传输索引或接收中目录；该段已异常结束，或原采集服务已退出、留下未完成的录制/收尾状态。正在采集、正常封装、正常传输的片段不能通过此入口删除。

- 后台先清理上位机并验证回执，再清理下位机，最后由实际缓存探测移除网页行；不通过隐藏记录冒充清理完成。
- 两端清理使用文件锁和身份核验；上位机RGB采集至编码结束期间持有每段锁。旧版未持锁片段在视觉录制服务仍运行时会拒绝清理，结束摇操服务后可重试。
- 失败时显示原因和“重试清理缓存”，保留记录及关机阻断；允许断连、回执丢失、部分清理后重试。网页服务重启后未确认的任务显示为待重试，不自动重新删除。
- 本机操作凭据：`.pipeline/cache_deletions/<recording_id>.json`；下位机凭据：`~/.cache/lejulab/vr_transfer/.invalid_deletions/<recording_id>.json`。这些只保留操作回执，不保留被删除的MCAP、图片或视频。
- 新接口：`POST /api/cache/delete`，需同源请求、工作台令牌、`recording_id`与明确的`confirm_permanent:true`。网页提交后立即返回，后台清理结果通过状态轮询显示。

| CANable1、CANable2（当前ttyACM1、ttyACM0） | 已枚举的USB转CAN设备，当前SocketCAN关节配置未使用 |

约每2秒更新一次。CAN显示接口是否开启、整条总线RX/TX帧率、当前内核状态、TEC/REC和累计warning/passive/bus-off，以及两次采样间新增错误和丢帧。帧率由内核报文计数差与下位机单调时钟差计算，不是动作50Hz或单电机反馈Hz。界面将ERROR-WARNING标记和实际收发分开显示；即使累计告警不变，也通过RX/TX是否停止识别断流，不把历史告警等同于本轮新故障。

硬件运行时，持续4秒没有新增接收/发送会显示停止；BUS-OFF、接口缺失和未开启立即显示。硬件未运行则显示待机，避免把正常停止当作通信故障。重启、计数回退、长时间断连或运行状态变化会重新建立取样基线。来源断连或超过7秒没有新状态时，运行状态和速率变为待确认，避免沿用绿色状态。

串口按当前/dev/serial/by-id及HIPNUC别名发现设备，显示连接和占用进程。只读查询现有文件描述符，不打开串口、不读取设备数据、不发送CAN帧、不改变接口参数。占用查询使用已有的sudo -n fuser权限；权限不足或查询超时明确显示待确认。串口已打开不等于传感器数据完整；CAN整条总线有流量也不保证每个电机都已回复。关节数值仍来自/rt/joint_state汇总数据。

下位机新增`vr_communication_probe.py`，由现有`vr_dashboard_probe.py`读取；本机`communication.py`计算速率并处理过期状态，数据位于`/api/state`的`feedback.communication`。无需新增用户服务；仅增加只读显示，不改变采集或启动的原有门槛。未改硬件、录制、传输、裁剪和对齐流程。


## 自定义任务 → L/R分类（2026-11-03）

网页“采集记录”左侧先选择任务，再用左右手筛选查看L、R或待分左右手。任务由使用者点击“新建任务”定义，本机目录使用同一名称。中文名称可用；不接受路径分隔符、保留名称、重复名称或过长名称。

已有片段：勾选一段或多段，选择“目标任务”，点击“归入任务”。整段原始、处理结果和人工标注一起移动到`vr_Data/任务名/R或L/时间目录/`；保留已有左右手。尚未设置左右手的放在任务下`unfiled`目录，之后勾选并点击“归到R/归到L”。跨任务重新归类同样保留左右手。只有传输校验、缓存清理回执和本机处理均完成的片段可归类。旧目录继续可读，已有未命名数据由使用者手动选择任务，不自动代填。

后续采集：在顶部“任务设置”选择任务及采集左右手，点击“应用任务”。录制服务将任务版本固定在每段元数据中；本机将该版本绑定到任务分类及左右手，接收校验和本机处理完成后自动归入相应目录。未选左右手时进入任务下`unfiled`；未应用自定义任务的片段保留在待分类区。LT+Y/LT+X、60FPS原片和首尾裁5秒/50Hz对齐流程保持现有设置。应用任务只影响之后开始的片段。

目录索引在`.pipeline/task_catalog.json`，采集版本绑定在`.pipeline/capture_tasks/`。稳定录制编号和`.pipeline/transfers/`接收索引跟随目录移动；`receipt.json`和`location.json`记录当前任务/左右手位置。原始采集任务快照、媒体、MCAP、校验清单和人工验收内容不因归类被改写。任务类目名与采集描述分别保存。

归类使用同数据盘原子重命名和持久日志；写入中断后在下次扫描恢复。失败不会覆盖目标，自动归档失败会在后续接收服务轮询重试，不重新接收或裁剪。回收站仍为`.trash/时间目录`，恢复时回到原任务和左右手目录。网页下载、50Hz审核及机器人3D按稳定编号解析当前位置。

无需新增服务。升级后重启本机`roban-vr-dashboard.service`和`roban-vr-workstation.service`，浏览器刷新即可。隔离任务验证根目录为`.pipeline/task_validation_20261103/`，其中任务和左右手示例仅属于测试副本。


## 回收站永久删除（2026-11-03）

“采集记录 → 回收站”支持单条“永久删除”、勾选后“永久删除所选”和“清空回收站”。操作首先显示本次片段列表、文件数量、预计释放空间和不可恢复说明；勾选确认框后才允许提交。取消确认不会删除文件。清空的范围固定为确认页中的录制编号；确认之后才移入回收站的片段不被包含。确认有效期为5分钟，记录恢复或变动后必须重新核对。

永久删除清理本机回收站中整段`raw`、`processed`、MCAP、RGB视频、时间戳、标注及对应审核视频缓存。原始接收、下位机缓存清理回执和本机处理必须已经结束，且片段必须仍在`.trash`中。永久删除不会向机器人发送命令或远程删除请求。

旧版匿名审核缓存无法精确对应录制编号，确认页会单独列出这些旧缓存数量并一并清理；其他正常片段可重新生成审核视频。新版审核缓存按`.pipeline/review_cache/recording_id/v2_<signature>/`隔离，只清理对应片段。共享文件按inode的磁盘块与链接数估算释放量，因此“文件合计”与预计释放空间可能不同；仍被其他文件或进程使用的数据块不保证立即释放。

清理在后台执行，网页显示“永久删除中”。已经提交永久删除的片段禁止恢复、归类和重新处理。如果清理中断或失败，显示“删除失败 · 可重试”及原因，允许确认后清理剩余文件；不会把部分删除的数据误当作完整片段恢复。服务重启后不自动继续不可恢复操作，而是提示确认后重试。

确认计划保存在`.pipeline/trash_purge_plans/`，删除完成仅保留少量录制编号/时间和删除回执索引，防止接收轮询或过期请求重新建立同一段数据；它不保留MCAP、视频、时间戳或人工标注。删除完成后采集列表与回收站均移除此片段。

## 每只手6维的50Hz导出（2026-11-04）

本机处理在首尾各裁5秒并生成身体/RGB的50Hz网格后，读取裁剪MCAP中的`/rt/hand_cmd`和`/rt/hand_state`，加入同一网格。两个话题均为12维，前6维左手、后6维右手。位置沿用Leju接口的0～100开合量（0张开、100闭合），不是rad或角度。六个通道按源序号保留，尚未核实的具体手指名称不代填。速度、电流、状态码保留驱动原值，非零状态码不直接解释成通信故障。

导出位于每段`processed/vision/hand_alignment.json`所指的不可变版本目录`hand_alignment/v1_<hash>/`。`aligned_50hz_with_hands.jsonl`保留原身体字段，新增`hands.left/right.action`（各6维指令）和`observation_state`（各6维实际位置）；`alignment.csv`增加源索引、时间、有效标记、年龄与原因，另有`schema.json`、统计、独立审计和SHA256清单。网页详情“文件与时间”可下载，统计中左右手分别显示有效条数。旧身体JSONL/CSV及原片继续保留，不能只读取旧21/23维文件便认为已含手部。

仅选择不晚于当前网格点的最新源消息，不插值，也不越过新的无效消息改选旧值。检查12维、有限数、位置范围、驱动左右有效位及时间顺序；指令年龄不超过50ms。反馈年龄为`网格时间 - hand_state消息时间 + 驱动sample_age_ms`；由于驱动年龄只有整数毫秒，额外计入1ms误差上限后要求不超过50ms。DDS发布约1000Hz不代表手部传感器刷新1000Hz。静止且有效的0值保留。

无效/超龄训练值为null，原值、驱动有效位、年龄和原因仍保存，不补零或静默删行。使用`hands.training_matched`选择训练有效样本；按采集设置的R/L判定所需手，未设置时要求双手。身体与视频通过不代表手部全部通过，网页显示“手部待复核”，不会把部分无效的数据宣称为完整合格训练片段。本版本不切分旧数据，也不将手部数组擅自拼接到身体数组。

后续LT+Y/LT+X完成后由现有接收服务自动处理。旧片段可用`python3 .pipeline/scripts/vr_hand_alignment.py --root <vr_Data目录> --recording-id <稳定录制编号>`补充或在重新分配左右手后刷新手部判定；只接受传输清理结束、未删除且身体/RGB处理完成的本机片段。它不重复裁剪，不改写MCAP、视频和原有身体表。生成失败保留上一版完整导出。新版处理的整体审计包含手部清单和独立源值核验；旧数据补充导出拥有独立审计及清单。
